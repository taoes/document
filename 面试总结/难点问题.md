1. iText2Pdf:  二进制执行
	1. 占用堆内存过高，生成超过 2K 条的数据就不行了
	2. 业务期望界面可调整，支持 HTML 设置
	3. 界面美观
	放弃需要发布的 JAVA 库，使用 HTML2PDF，但是存在性能问题，使用 ForkJoin 的方案单页输出，每个限制在 10M，快速的回收内存，完成按序号合并
2. 资损接口稳定性保障
	1. 城代校区的订单降税，采用 Redis+本地缓存自动切换的能力
	2. 支持 1200QPS，一旦 Redis 出现抖动或者超出预期时间 10ms，自动执行本地缓存
	3. Redis 长时间不可用，使用乘性退让算法， 保证业务 0 错误
	4. 本地数据定时从 Redis 同步，一直支持 MQ通知异步刷新
	5. 上游接收 MQ 订单消息，若失败，支持阶梯时间重试和后续兜底
3. 审批流或者其他业务系统中 OSS 链接过期的问题，法务规定不能超过 10 分钟，接口提供方不愿意调整，业务预期 2 天内审核完成
	1. 方案 1: 放置一个新的页面，新页面里面展示全部附件，体验不好
	2. 方案 2: 自建审批流： 成本高，存在重复造轮子，不具有动态调整，通用性
	3. 数据固化或者已经归档，但是文件仍然存在访问诉求，比如法务问题，审批超时了
	4.  使用 302 临时重定向，让浏览器自动化获取最新的链接，保证即时在链接超时的情况下也可以正常展示文件，同时也防止文件时间过长的风险问题
