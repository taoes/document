## 2、 问题

## ① 基础原理

  

**1. 什么是 RAG？完整流程是怎样的？** ◆

答题方向：三段式——**索引**（文档解析 → 分块 → Embedding → 向量入库）、**检索**（Query 向量化 → 召回 Top-k → 可选重排）、**生成**（检索结果拼装 Prompt → LLM 生成）。核心价值：外挂私有/实时知识、降低幻觉、答案可溯源。


**2. RAG 为什么还会产生幻觉？** ◆

答题方向：检索不相关（召回失败）、证据互相冲突、LLM 过度自信忽略上下文、知识缺失但没拒答。
- 治理链路：混合检索 + 重排提召回精度 → Prompt 约束 → 引用校验 → 相关性阈值拒答。


**3. RAG vs 微调 vs 长上下文，怎么选？** ◆

答题方向：
- **微调**改行为/风格，学新知识易过拟合、成本高、更新慢；
- **长上下文**贵、延迟高、长文利用不充分（"lost in the middle"）；
- **RAG** 知识实时、可溯源、可控，适合私有与时效知识。实际常组合：RAG 管知识，微调管语气格式。

**4. 什么时候不该用 RAG？** ○

答题方向：知识高度稳定且量小（直接写进 Prompt）、需要深度推理（可能要用 CoT/微调）、对延迟成本极敏感、已有可靠微调方案。

  

## ② 索引构建

**5. PDF / 扫描件 / 表格怎么处理？** ○

答题方向：版面分析（Layout）+ OCR；
- 表格转 Markdown/HTML 保留结构而非纯文本流；
- 按标题层级建父子块；注意 PDF 文本抽取的阅读顺序错乱问题。

**6. 分块策略有哪些？块大小怎么定？** ◆

答题方向：
- 固定大小 + overlap、递归字符分块、按文档结构（标题/段落）、语义分块（Embedding 相似度断点）。块小粒度细但割裂语义，块大语义完整但稀释向量、浪费 Top-k。
-  块大小要和 Embedding 窗口、检索粒度、生成需求对齐。


**7. chunk overlap 的作用是什么？** ◆

答题方向：防止语义边界被切开导致信息丢失，常见 10%-20% 重叠；代价是索引膨胀和召回重复。

  

**8. Embedding 模型怎么选？中文场景推荐？** ◆
答题方向：中文常用 BGE（bge-large-zh、bge-m3 多语）、M3E、OpenAI text-embedding-3、国产模型（千问/智谱）。看维度（维度高精度高成本高）、最大长度、领域数据匹配度；注意 Query 和文档编码器的一致性（部分模型有 query 指令前缀）。

  
**9. 向量引与相似度计算怎么选？** ☆
答题方向：归一化后 cosine ≈ dot；索引选 HNSW（图索引，权衡 efConstruction/efSearch/M，召回高）、IVF（粗聚类 + 倒排，省内存快但召回略降）、PQ/SQ 量化（压缩但精度损失）。工具：FAISS / Qdrant / Milvus / pgvector。

  
**10. 为什么要加元数据？怎么用？** ☆
答题方向：文档名、页码、章节、时间、权限标签。用途：过滤（metadata filter）、引用溯源展示、权限控制（chunk 级 RBAC）、结果可解释。

  
## ③ 检索召回

**11. 向量检索 vs BM25 vs 混合检索？** ◆

答题方向：向量抓语义但忽略精确词，BM25 抓精确匹配（专有名词、代码、ID、型号场景更强）。混合检索 = 两路并行 + 融合，是生产标配。


**12. RRF 融合原理是什么？** ◆
答题方向：`score = Σ 1/(k + rank_i)`，k 通常取 60。不依赖各路分数分布，只需排名，简单鲁棒，无需调权重。

  **13. Top-k 怎么选？要不要相关性阈值？** ◆
答题方向：Top-k 与块大小、任务精度负相关，通常 3-10；低相关结果建议过滤（阈值或 LLM 判断），否则噪音进上下文反而拖累生成。


**14. HyDE 是什么？有什么代价？** ☆
答题方向：先让 LLM 生成"假设答案"，再用它做向量检索，拉近 Query 与文档的语义距离。代价：多一次生成调用、延迟增加，假设答案本身可能引入偏差。

  
**15. 查询改写 / 多轮重写怎么做？** ☆
答题方向：多轮场景用 LLM 把对话历史压缩成独立 Query（condense）；单轮可做同义词扩展、子问题分解（多跳问题拆成多个检索）。


**16. 多路召回怎么设计？** ☆
答题方向：向量 + BM25 + 关键词 + 知识图谱/结构化库并行召回，RRF 或 reranker 融合；先宽召回（如 Top-50）再精排，兼顾召回率和精度。



## ④ 重排与生成


**17. Rerank 的原理？bi-encoder 和 cross-encoder 区别？** ◆

答题方向：bi-encoder 独立编码、可预计算，适合亿级召回；cross-encoder 把 query 和 doc 拼接做交互注意力，精度高但无法预计算，只对 Top-N 精排。经典模型 BGE-reranker、Cohere rerank。**"为什么不用 cross-encoder 直接检索"是高频追问**。

  

**18. 检索结果怎么组装进 Prompt？有哪些约束技巧？** ◆

答题方向：明确"只基于给定上下文回答"、给每段编号并强制引用 [1][2]、"不知道就说不知道"、指令在证据之前；控制 token 预算，超限按相关性截断。

  

**19. 引用溯源怎么落地？** ◆

答题方向：chunk 带元数据（文档/页码/章节），Prompt 要求答案标注来源编号，后端校验引用编号确实存在且内容可对应，前端渲染来源链接。可加"证据是否支持答案"的校验步骤。

  

**20. 检索结果与问题无关怎么办？** ◆

答题方向：两层防护——召回层相关度阈值/重排过滤；生成层让 LLM 判断"上下文是否足够"，不足则拒答或触发重新检索（对应 CRAG 思路）。

  

**21. 长上下文时代还需要 RAG 吗？** ☆

答题方向：需要。成本、延迟、长文利用效率仍是痛点；长上下文适合少量强相关文档，RAG 适合大规模知识库，二者可混合（先 RAG 召回再整篇塞入）。

  

## ⑤ 评估体系

  

**22. 检索侧指标有哪些？各自含义？** ◆

答题方向：**Recall@k**（前 k 条命中相关文档比例）、**Precision@k**、**MRR**（第一个相关结果排位的倒数）、**NDCG**（位置加权，越靠前权重越大）。

  

**23. 生成侧指标有哪些？** ◆

答题方向：**Faithfulness**（答案是否被检索上下文支持，查幻觉）、**Answer Relevance**（是否回答问题）、**Context Relevance**（上下文是否相关，可选）。RAGAS 框架即基于这三类，LLM-as-judge 打分。

  

**24. 没有标注数据怎么评估？** ○

答题方向：LLM-as-judge（注意偏置，可用成对比较）、人工抽样、间接信号：引用命中率、拒答率、用户反馈/点踩、答案可溯源比例。

  

**25. 线上怎么监控 RAG 质量？** ☆
答题方向：检索命中率、平均召回相关性、回答含引用率、拒答率、延迟（检索/生成分阶段）、成本（token）；灰度 A/B 对比新策略；日志里保留 query/检索结果/答案用于离线回放。

  

## ⑥ 进阶架构

  

**26. Agentic RAG 是什么？Self-RAG / CRAG 呢？** ☆

答题方向：让 LLM 自主决策检索动作。**Self-RAG**：模型自我反思，决定要不要检索、检索是否相关、回答是否被支持；**CRAG**：检索质量评估器 + 知识精炼，检索差时触发 Web 搜索兜底；**Router**：先分类再选数据源/工具。可以用 LangGraph 描述状态机实现。

  

**27. GraphRAG 解决什么问题？** ☆

答题方向：微软提出，实体关系抽取构建知识图谱，社区检测 + 分层次摘要，解决传统 RAG 的**多跳推理**和**全局性问题**（如"整个语料讲了什么"）；代价是构建成本高、延迟大，适合全局理解场景。

  

**28. 多轮对话中的 RAG 怎么做？** ☆

答题方向：历史 Query 压缩重写（避免代词指代丢失）、按会话增量检索、长记忆与短期上下文分层、检索时结合会话意图。

  

**29. 多文档 / 多源 RAG 有哪些坑？** ☆

答题方向：文档间重复内容（去重）、证据冲突（置信度/多数投票/时间优先）、子库路由（按领域分库，先路由再检索）、跨文档引用归并。

  

**30. 生产环境 RAG 的难点有哪些？** ☆

答题方向：数据更新（增量索引、双写、tombstone、定时重建）、权限隔离（chunk 级过滤，防越权）、**提示注入**（文档内容伪装指令，需把检索内容当数据不当指令）、语义缓存降成本、向量库容量与量化、延迟预算。
