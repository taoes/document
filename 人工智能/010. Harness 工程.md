# Harness Engineering（驾驭工程，面试口述版）

> 名词：驾驭工程，英文 Harness Engineering，2026 Agent面试高频新概念。 核心公式：**Agent = Model（大模型） + Harness（驾驭系统）**

## 一、一句话定义（背这句）

驾驭工程不是调模型、不是单纯写prompt，而是**在大模型外面，搭建一套完整可控的运行环境、约束规则、校验闭环与可观测体系**；目标是约束Agent行为、拦截错误、防止失控，让Agent能稳定、安全、可复盘地在生产系统执行任务。

> 比喻：模型是烈马，Harness就是缰绳、马鞍、护栏；马本身的能力不变，但靠这套装备才能安全干活。

### 三代AI工程范式对比（面试官大概率追问）

1. **Prompt工程**：调话术，优化单次输入输出，解决“怎么跟模型说话”；适合简单问答。
2. **上下文工程 Context Engineering**：管理上下文、RAG检索、记忆管理，解决“给模型喂什么信息”。
3. **驾驭工程 Harness Engineering**：系统级管控，解决**Agent能做什么、不能做什么、出错怎么拦截、怎么终止、如何审计**，面向长任务、工具调用、生产落地。

> 关键认知：模型决定上限；**Harness决定系统能不能上线生产**。

## 二、驾驭工程核心组件（五大模块）

1. **状态与编排层** 用状态机/LangGraph管理Agent全局状态、任务步骤，记录每一步thought、action、observation；控制循环、分支、最大迭代次数，防止死循环。
2. **工具执行与沙箱层** 工具网关、权限白名单、沙箱隔离、幂等控制；**高危操作人工审批（Human-in-the-loop）**。 不是Agent直接调用业务接口，全部请求经过Harness网关校验。
3. **校验与防护层（Guardrail护栏）**
    - 输入校验：prompt注入检测、意图识别；
    - 入参Schema校验：工具调用参数合法性校验；
    - 输出校验：事实校验、合规检查、幻觉拦截；
    - 终止规则：任务完成判断、超时、最大步数限制。
4. **记忆与上下文解析层** 统一管理短期对话记忆、长期向量记忆；动态裁剪、摘要、检索召回，控制token，不会无脑把全部历史塞给LLM。
5. **可观测&评估闭环（AgentOps）** 全链路日志、每一步trace埋点、token统计、耗时、错误告警；**自动评估+人工标注回流**，发现错误后固化规则，防止同类问题再次发生。
    
    > Harness核心思想：**只要Agent踩坑，就工程化加一层防护，避免下次重复犯错**，而不是只靠prompt去约束。
    

## 三、如何落地（面试重点，企业Agent项目怎么搭建Harness）

> 基于LangGraph / LangChain4j都可以实现Harness体系，不是独立新框架，是一套工程架构思想。

### 落地步骤

1. **定义边界与权限** 先梳理Agent可用工具白名单，区分普通查询工具和高危工具（修改数据库、发消息、删除数据）；高危操作强制人工审批。 给每个工具定义严格的JSON Schema，Harness网关做入参校验，非法参数直接拦截，不交给模型重试。
2. **状态机编排（LangGraph）** 用State保存任务全生命周期数据，状态流转：初始化 → 规划思考 → 工具调用前置校验 → 执行工具 → 结果校验 → 判断是否继续/终止。 硬约束：设置最大迭代步数、单次任务超时时间，防止死循环。
3. **三层校验链路（Harness最核心）**
    - **前置校验（调用工具前）**：意图检测、权限校验、参数合法性校验；
    - **执行层**：沙箱、幂等，避免重复提交业务操作；
    - **后置校验（拿到工具返回/模型输出后）**：校验结果是否合规、是否存在冲突、是否和知识库事实矛盾，异常时触发重试或直接中断任务。
4. **记忆与上下文Resolver（解析器）** 不是把所有历史一股脑丢进prompt。Resolver根据当前任务状态，动态检索、筛选、压缩上下文，按需注入RAG文档、历史记忆，控制token成本。
5. **可观测 + 持续迭代闭环** 每条Agent任务生成一条完整Trace：每一步思考、工具调用、入参、返回结果、token消耗。 收集失败样本，自动评测（LLM-as-judge打分），发现失败case，**新增护栏/校验规则**，沉淀到Harness系统，而不是单纯改prompt。

### 简化架构图

```
用户请求 → Harness网关（意图/安全校验） → LangGraph状态编排
        ↓
    LLM思考决策 → Harness前置校验 → 工具沙箱执行
        ↓
    工具结果返回 → Harness后置校验 → 判断是否继续循环
        ↓
    最终输出 + 完整审计日志
```

## 四、Harness落地常见坑（面试官爱问）

1. 只依赖prompt做约束，没有代码层面的护栏。**prompt很容易被绕过，必须用代码硬规则兜底**。
2. 没有幂等控制：Agent网络超时重复调用工具，造成重复写业务数据。
3. 状态管理简单粗暴，不记录工具调用历史，容易死循环。
4. 缺少可观测：Agent执行黑盒，出错不知道在哪一步翻车。
5. 校验太重，带来巨大性能开销：校验逻辑分级，轻量用代码规则，复杂事实校验才调用LLM Judge。

## 五、面试一句话总结（1分钟口述精简版）

驾驭工程是一套Agent外围的工程管控体系，核心是**模型+驾驭系统**。通过状态编排、工具网关、多层校验护栏、沙箱隔离、全链路观测，把Agent的行为约束在安全边界内。区别于Prompt和上下文工程，它强调用代码和系统规则兜底，而不是单纯靠提示词。每当Agent出现错误，我们就新增一层工程防护，避免同类错误重复发生，让Agent可以规模化上生产。

## 面试官高频连环追问&简短答案

### 1. Harness和LangGraph是什么关系？

LangGraph是**状态编排框架，是实现Harness的载体**，但LangGraph本身不等于Harness。Harness包含网关、校验、沙箱、审计、评估闭环这些外围管控组件。

### 2. Harness和Guardrails护栏的区别？

Guardrails是Harness其中一个子集（安全校验）；Harness是完整体系，包含编排、记忆、工具执行、观测、评估闭环。

### 3. 什么时候才需要做Harness？简单RAG应用需要吗？

简单问答RAG不需要。**只要Agent需要自主循环调用工具、操作业务数据、长任务执行、上生产环境**，就必须引入Harness这套驾驭体系。

### 4. 幂等在Harness里怎么做？

每个工具调用带上唯一request_id，Harness网关记录执行记录；相同任务+相同参数，直接返回缓存结果，防止重复执行写操作。高危操作还要加人工审批。

### 5. Harness工程在Java（LangChain4j）项目怎么落地？

用Java实现工具网关、参数校验、权限拦截；LangChain4j做Agent和工具调用；状态可以存在数据库，自行实现有限状态机；后置校验可以单独调用LLM Judge服务。
