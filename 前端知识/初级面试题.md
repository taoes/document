# 一、JavaScript 核心（重中之重，薄弱优先学这块）

## 1. var / let / const 的区别

### 知识点讲解

1. **作用域**

- var：**函数作用域**，只有在函数内部声明才会隔离；在if/for里面写var，外部也能访问。
- let / const：**块级作用域**，`{}`包裹就是一个块（if、for、while），块外面拿不到。

2. **变量提升** 所有var会提升到当前作用域顶部；但是**不会初始化**。 let/const也存在提升，但是进入「暂时性死区TDZ」：在声明之前不能访问，访问直接报错。
3. **重复声明** var 允许重复声明同一个变量，后面覆盖前面；let/const 同一作用域不能重复声明。
4. **const**：声明**常量**。**不能修改引用地址**。
    
    > const 存对象：不能重新赋值新对象，但是对象里面属性可以修改。
    

### 口述答案

var是函数作用域，存在变量提升，可以重复声明。let和const是块级作用域，存在暂时性死区，不能重复声明。const代表不能修改引用，如果是对象，对象内部属性可以修改。

### 追问坑点

问：什么是暂时性死区？ 答：变量提升了，但是在代码执行到声明语句之前，不能读取这个变量，这段区间叫TDZ，读取直接抛错。

## 2. 原型 & 原型链

### 知识点讲解

JS是基于原型的面向对象，没有类（ES6 class只是语法糖）。

1. 每一个**对象**都有`__proto__`（隐式原型），指向它的构造函数的`prototype`（显式原型）。
2. 每一个函数都自带`prototype`原型对象。
3. 当访问对象的属性/方法：**先在对象本身查找，找不到，就沿着__proto__向上查找，直到找到null**，这条查找链条就是原型链。
4. `instanceof`原理：沿着原型链看，构造函数的prototype是否出现在实例的原型链上。

```
const obj = {}
console.log(obj.__proto__ === Object.prototype)
```

### 口述答案

JS每个对象有隐式原型`__proto__`，每个函数有显式原型`prototype`。访问对象属性时，如果对象本身没有，就沿着`__proto__`一直向上查找，直到null，这条链就是原型链。instanceof就是遍历原型链判断。

### 追问

class的本质？class是原型的语法糖，底层依然是原型。

## 3. this 的指向（高频，很容易乱）

### 知识点讲解

this**不是定义时确定，是调用的时候确定**！5种绑定规则，优先级从高到低：

1. `new`绑定：new 构造函数，this指向**新创建的空对象**
2. 硬绑定：call / apply / bind，this绑定到传入的第一个参数
3. 隐式绑定：`obj.fn()`，fn里面this指向obj（调用的对象）
4. 默认绑定：普通函数直接调用，this指向全局（浏览器window，node全局global）；严格模式下变成undefined
5. 箭头函数：**没有自己的this**，不适用上面4条规则。继承外层作用域的this。
    
    > 重点：箭头函数不能new，没有arguments。
    

### 口述答案

this是**调用时决定**。new优先级最高，其次call/apply/bind硬绑定，然后对象方法隐式绑定，普通函数默认绑定全局。箭头函数没有自己this，继承外层作用域的this。

### 坑

```
const obj = {
  a: 1,
  fn: () => {console.log(this.a)}
}
obj.fn() // 拿不到obj，箭头函数this是外层全局
```

## 4. 闭包 Closure

### 知识点讲解

**定义：一个函数可以访问另一个函数作用域中的变量，即使外层函数已经执行完毕。** 形成条件：内层函数引用外层函数变量，内层函数被拿到外层执行。

用途：

1. 保存私有变量，做数据隔离
2. 防抖、节流、回调、定时器保存上下文 缺点： 外层函数变量不会被GC回收，**容易造成内存泄漏**。需要手动释放引用。

例子：

```
function outer() {
  let count = 0
  return function inner() {
    count++
    console.log(count)
  }
}
const fn = outer()
fn()
fn()
```

outer执行完，按理说局部变量销毁；但是inner形成闭包，count保留。

### 口述答案

当内部函数引用外部函数的变量，并且内部函数被外部执行，就形成闭包。外层函数执行结束，变量依旧保存在内存。可以用来实现私有变量、防抖节流。缺点：长期持有变量，容易内存泄漏。

### 追问：内存泄漏怎么解决？

把闭包引用置为null，切断引用，让垃圾回收器回收。

## 5. 事件循环 EventLoop / 宏任务 & 微任务【超级高频】

### 知识点讲解

JS是**单线程**，同一时间只能做一件事。为了处理异步，设计事件循环。 执行顺序口诀：

> 先执行同步代码 → 全部同步跑完 → **一次性清空所有微任务** → 取一个宏任务执行 → 再清空全部微任务，循环往复。

✅ **微任务（Microtask，优先级高）** Promise.then/catch/finally、await后面代码、queueMicrotask、MutationObserver

✅ **宏任务（Macrotask）** setTimeout、setInterval、ajax请求、DOM渲染、script整体代码

> await 本质是Promise语法糖，await之后的代码，放进微任务队列。

### 口述答案

JS单线程，通过事件循环处理异步。执行顺序：先执行所有同步代码；同步结束，清空所有微任务；然后执行一个宏任务，之后再次清空微任务，不断循环。微任务包含Promise.then、await，宏任务包含setTimeout、ajax。

### 追问坑

问：setTimeout一定准时吗？ 答：不一定。只是到时间把回调放进宏任务队列；如果主线程还有长任务，会阻塞，延迟执行。

## 6. Promise

### 知识点讲解

Promise是异步解决方案，用来解决回调地狱。 三种状态，**状态不可逆，只能从pending变成fulfilled或者rejected**

- pending：等待中（初始状态）
- fulfilled：成功
- rejected：失败

API：

- `.then(res=>{})`：成功回调，返回新Promise，可以链式调用
- `.catch(err=>{})`：捕获失败，返回新Promise
- `.finally()`：不管成功失败都会执行，不接收参数

静态方法： Promise.all：全部成功才成功；任意一个失败直接reject Promise.race：谁先完成就返回谁，不管成功失败 Promise.allSettled：全部执行完，收集所有结果（成功失败都拿）

### 口述答案

Promise处理异步，有pending、fulfilled、rejected三种状态，状态一旦改变不能回退。then支持链式调用。all等待全部成功；race竞速，第一个完成就返回；allSettled拿到所有结果。Promise回调属于微任务。

## 7. async / await

### 知识点讲解

async 修饰函数，**函数永远返回Promise**。 await 后面跟Promise；**await会暂停当前async函数执行，等待Promise完成，再继续执行后面代码。await后面代码包装进then回调，属于微任务**。

错误处理：await的异常必须用 try catch捕获；如果不捕获，会变成rejected Promise。

```
async function demo(){
  try{
    const res = await fetch()
  }catch(e){
    console.error(e)
  }
}
```

### 口述答案

async是函数修饰符，返回Promise。await暂停async函数，等待Promise完成，后面代码属于微任务。await报错需要try/catch捕获。

## 8. 深浅拷贝

### 知识点讲解

JS里分基本类型（string/number/boolean/null/undefined）和引用类型（对象、数组）

- 基本类型：赋值直接拷贝值，互不影响
- 引用类型：变量存的是**内存地址**

浅拷贝：**只拷贝第一层**。如果属性是引用类型，新对象和原对象共用同一个内存地址。修改引用属性互相影响。 浅拷贝方式：`Object.assign`、`{...obj}`扩展运算符、数组slice。

深拷贝：递归遍历所有层级，全部创建新内存。修改新对象完全不影响原对象。 简单方案：`JSON.parse(JSON.stringify(obj))` 缺陷：无法拷贝函数、undefined、Symbol，遇到循环引用直接报错。 生产要用手写递归或者lodash.cloneDeep。

### 口述答案

浅拷贝只拷贝第一层，引用类型共用内存，修改互相影响。扩展运算符、Object.assign都是浅拷贝。深拷贝递归复制所有层级，完全独立。JSON序列化方案简单但是有缺陷，不支持函数、循环引用。

## 9. 防抖、节流

### 知识点讲解

都是**限制高频触发的函数执行**（比如搜索输入、滚动、窗口resize）

防抖 debounce：**触发事件后，延迟N秒执行；如果N秒内再次触发，重新计时。** 场景：搜索框输入联想，用户连续打字，等用户停手再请求接口。

节流 throttle：**规定一段时间内，函数最多执行一次。固定频率执行。** 场景：滚动监听、鼠标移动，控制每隔200ms执行一次。

一句话区分：防抖是**合并多次，等停止才执行**；节流是**稀释频率，固定间隔执行**。

### 口述答案

防抖：事件触发后延迟执行，期间再次触发就重置计时器，适合搜索输入。节流：单位时间最多执行一次，控制触发频率，适合滚动监听。

# 二、浏览器相关（非常高频，偏后端岗位爱问）

## 10. 浏览器渲染流程

### 知识点讲解

1. HTML解析，生成DOM树（文档结构）
2. CSS解析，生成CSSOM树（CSS样式）
3. DOM + CSSOM合并，生成**渲染树Render Tree**：只包含需要显示的节点，display:none不会进渲染树
4. Layout 布局（重排Reflow）：计算每个元素的位置、宽高
5. Paint 绘制（重绘Repaint）：填充像素，颜色、图片
6. Composite 分层合成：页面分层，GPU绘制，跳过布局和绘制，性能最高

> transform、opacity会触发合成，不触发重排重绘。

### 口述答案

HTML生成DOM，CSS生成CSSOM，合并得到渲染树。Layout布局计算位置大小；Paint绘制像素；最后Composite分层合成。transform动画走合成层，性能更好。

## 11. 重排 Reflow / 重绘 Repaint

### 知识点讲解

- **重排 Reflow**：元素几何信息（宽高、位置、布局）发生变化，浏览器重新计算布局。**开销很大**。 例子：修改width、height、margin、offsetTop。
- **重绘 Repaint**：元素样式改变，但是布局不变。只重新绘制像素。开销比重排小。 例子：color、background。

优化手段：

1. 不要频繁读取布局属性（offsetWidth），浏览器会强制刷新队列
2. 批量修改样式：预先写好class，一次性修改class
3. 使用文档碎片fragment，一次性插入DOM
4. 动画优先使用transform、opacity，触发合成层，跳过重排重绘

### 口述答案

重排是元素位置大小变化，浏览器重新计算布局，开销高。重绘只是颜色等样式改变，不改变布局。优化：批量修改样式，动画优先transform，减少读取布局属性。

## 12. 同源策略 & 跨域

### 知识点讲解

同源策略是浏览器的安全策略：**协议、域名、端口，三者全部相同才算同源。任意一个不同就是跨域**。 跨域不是请求发不出去，**请求正常到达后端，后端也返回数据；但是浏览器拦截JS读取响应**。

跨域解决方案：

1. CORS（后端配置响应头，生产首选）
    - 简单请求：浏览器直接发送请求，后端返回Access-Control-Allow-Origin
    - 非简单请求（带自定义header、content-type为application/json）：先发OPTIONS预检请求
2. 开发环境代理：vite/webpack代理，前端请求同域，工具转发请求到后端（只用于本地开发）
3. Nginx反向代理，服务器层面转发
4. JSONP：利用script标签不受同源限制，**只支持GET请求，不安全，现在很少用**

### 口述答案

同源策略是浏览器安全限制，协议域名端口任一不同就是跨域。请求能到达后端，浏览器拦截JS读取返回结果。常用方案：后端配置CORS；本地开发使用前端打包工具代理；线上Nginx反向代理。JSONP仅GET，基本淘汰。

### 追问：简单请求和预检请求区别？

简单请求不会发送OPTIONS；非简单请求先发OPTIONS预检询问服务器是否允许跨域。

## 13. Cookie / LocalStorage / SessionStorage

### 知识点讲解

1. Cookie 容量4KB。每次http请求**自动随请求头发送给后端**。可以设置HttpOnly、Secure、过期时间。HttpOnly：JS无法读取，防止XSS偷Cookie。
2. LocalStorage 容量约5MB，永久保存在本地，除非手动删除。**不会随http请求上传**。同域名共享。
3. SessionStorage 5MB，页面会话级别。关闭标签页直接清空。**不同标签页不共享**。不会随请求上传。

### 口述答案

Cookie 4k，每次请求自动传给后端，可以设置HttpOnly。LocalStorage永久存储，同域名共享，不会上传请求。SessionStorage仅当前标签页会话有效，关闭标签销毁，不跨标签共享。

## 14. XSS 和 CSRF（安全，偏后端岗位必考）

### XSS 跨站脚本攻击

原理：攻击者注入恶意JS代码到页面，其他用户打开页面，JS在用户浏览器执行。 三类：

1. 存储型XSS：恶意代码存入数据库，所有人访问页面都会触发（危害最大，比如评论区）
2. 反射型XSS：恶意代码放在URL参数，点击链接触发，不存入数据库
3. DOM型XSS：纯前端JS把url内容直接插入DOM，不经过后端返回

防御：

1. 输入输出转义（转义< > & " '）
2. CSP 内容安全策略，限制脚本来源
3. Cookie 设置HttpOnly，JS无法读取Cookie

### CSRF 跨站请求伪造

原理：用户登录A网站，浏览器保存A网站cookie。用户在同一个浏览器打开恶意网站，恶意网站偷偷发起请求访问A网站，浏览器自动带上cookie，冒充用户操作。

防御：

1. 接口增加token，每次请求前端携带token，后端校验（最常用）
2. 校验请求Referer来源
3. 关键接口使用验证码

### 口述答案

XSS：注入恶意JS在页面执行。防御：输入转义、CSP、HttpOnly Cookie。 CSRF：利用用户浏览器自动携带Cookie，冒充用户发起请求。防御：使用token校验，校验referer。

## 15. HTTP缓存（强缓存、协商缓存）

### 知识点讲解

目标：减少网络请求，加速页面加载。

1. **强缓存**：Cache-Control / Expires 浏览器看资源有没有过期，**不发请求，直接读取本地缓存** Cache-Control: max-age=xxx（推荐，相对时间，优先级高于Expires） Expires：绝对时间，老标准。
2. **协商缓存**：强缓存失效，浏览器发请求到服务器，服务器判断资源是否改动

- Last-Modified + If-Modified-Since：文件修改时间
- ETag + If-None-Match：资源内容唯一哈希标识，优先级更高 服务器资源没变化，返回304 Not Modified，浏览器继续用本地缓存；资源改动返回200+新资源。

> 优先级：强缓存 > 协商缓存；ETag优先级高于Last-Modified

### 口述答案

HTTP缓存分强缓存和协商缓存。强缓存使用Cache-Control，不发送请求直接读本地缓存。强缓存过期触发协商缓存，浏览器发请求校验，使用ETag或者Last-Modified。资源不变返回304，复用缓存。ETag优先级高于Last-Modified。

# 三、网络请求

## 16. axios vs fetch

### 知识点讲解

fetch：浏览器原生API，基于Promise 缺点：

1. 4xx/5xx 不会触发reject，只有网络断连才报错，状态码错误需要手动判断
2. 没有请求/响应拦截器
3. 没有超时取消请求（AbortController是后来新增）
4. 不能自动转换json，需要手动 .json()

axios：第三方库，底层XMLHttpRequest 优点：自带拦截器、超时、自动转JSON、取消请求、请求转换。

### 口述答案

fetch是浏览器原生API，基于Promise；4xx5xx不会reject，缺少拦截器，需要手动处理响应。axios是基于XHR封装库，自带请求响应拦截、超时、自动json转换，项目更常用。

# 四、TypeScript

## 17. TS作用

TS是JS超集，添加静态类型。编译阶段做类型校验，编译成JS运行。 好处：

- 编译期捕获类型错误，不用等到线上运行报错
- IDE智能提示，代码可读性，适合大型项目
- 约束入参返回值，前后端接口契约

口述答案：TS为JS增加静态类型，编译阶段检查类型错误，提升IDE提示，方便大型项目维护，编译输出JS。

## 18. interface 和 type 区别

1. interface：**接口，专门描述对象结构**，支持**声明合并**。多次写同名interface，自动合并。可以extends继承。
2. type：类型别名，可以定义任意类型（联合、交叉、基础类型），**不能重复声明**。

> 日常开发：描述对象优先interface；联合类型、复杂复合类型用type。

口述答案：interface描述对象结构，支持声明合并，可以extends。type是类型别名，可以定义联合交叉类型，不支持重复声明。对象优先interface，复杂复合类型用type。

## 19. 泛型

泛型就是**类型参数**。函数/组件不固定类型，调用的时候再传入类型，实现类型复用。 例子：`function get<T>(arg:T):T {return arg}` T是类型占位符，调用时 `get<string>("abc")`

口述答案：泛型是类型参数，编写通用函数、组件，类型不写死，调用时传入具体类型，实现代码复用，保留类型推导。

# 五、Vue3（你的技术栈）

## 20. Vue3对比Vue2改进

1. Composition API，更好逻辑复用，TS友好
2. 响应式换成Proxy，代理整个对象，解决Vue2 Object.defineProperty缺陷（无法监听新增属性、数组下标）
3. Tree-Shaking，按需引入，打包体积更小
4. Fragment，支持多根节点
5. Teleport、Suspense内置组件

口述答案：Vue3新增Composition API，方便逻辑复用；使用Proxy做响应式，可以监听新增属性；支持Tree-shaking，多根节点，对TS支持更好。

## 21. Composition API vs Options API

Options API：data、methods、computed分开写。同一个业务逻辑分散在不同选项，大项目不好维护。 Composition API：按业务逻辑聚合，把相关变量和方法抽到同一个组合函数（useXXX），可以跨组件复用逻辑，TS友好。

口述答案：Options API按配置项分割代码，业务逻辑分散。Composition API按业务聚合代码，可以抽离组合函数，方便复用，TS支持更好。

## 22. Vue3响应式原理 Proxy

Proxy代理对象，可以拦截对象的get、set、deleteProperty操作。

- reactive：处理对象、数组
- ref：处理基础类型，包装成RefImpl对象，需要.value

依赖收集：get的时候收集当前effect副作用；set的时候触发收集的effect，更新视图。

口述答案：Vue3使用Proxy代理对象，拦截读写操作。reactive处理引用类型；ref包装基础类型。读取触发依赖收集，修改触发副作用更新视图。

## 23. ref 和 reactive

ref：可以处理基础类型和对象；返回RefImpl包装对象，访问值需要`.value`；模板自动解包，模板里不用写.value。 reactive：**只能接收引用类型（对象数组）**，不能传基础类型，不用.value。

口述答案：ref支持基础类型，返回包装对象，脚本内访问需要.value。reactive仅支持对象、数组，不需要.value。

## 24. computed 和 watch

computed：**计算属性，惰性，带缓存**。只有依赖的值发生变化，才重新计算。适合**派生数据**（由其他数据算出来的值）。不能做异步。 watch：监听数据变化，执行回调，**无缓存**。适合异步操作，复杂副作用。

口述答案：computed是计算属性，惰性缓存，依赖变化才重新计算，适合派生数据，不能异步。watch监听数据变化执行回调，无缓存，适合异步、副作用场景。

## 25. v-if vs v-show

v-if：条件渲染，条件为false，DOM直接销毁；true时重建DOM。**切换开销大，初始渲染开销小**，适合很少切换。 v-show：css display:none控制，DOM一直存在。**初始开销大，频繁切换性能更好**。

口述答案：v-if是销毁重建DOM，切换开销大。v-show通过display隐藏DOM，节点保留。频繁切换优先v-show。

## 26. nextTick

DOM更新是**异步批量更新**。修改响应式数据，DOM不会立刻更新。nextTick回调会在DOM更新完成后执行，可以拿到更新后的DOM。

口述答案：Vue DOM更新是异步。nextTick在DOM渲染完成后执行回调，用于获取更新后的DOM元素。

# 六、工程化 Vite / Webpack

## 27. Webpack核心概念

entry：入口文件 output：打包输出产物 loader：处理非js文件（css、图片），转译文件 plugin：打包全过程钩子，做额外功能（html生成、压缩、清理目录） mode：development / production

口述答案：webpack五个核心：entry入口，output输出，loader转译资源，plugin执行打包钩子，mode区分环境。

## 28. Vite为什么开发环境比webpack快

Webpack开发环境：**提前打包全部模块，生成bundle**，项目越大越慢。 Vite开发环境：基于浏览器原生ES Module，**不提前打包全部代码**；浏览器请求模块时按需编译。 生产环境：vite底层使用rollup打包。

口述答案：Vite开发环境利用浏览器ES Module，按需编译，不需要一次性打包全部代码，启动快。生产环境使用rollup打包。

## 29. Tree-Shaking

打包时删除代码中**没有被使用的代码**。前提：使用ES Module（import/export），不能CommonJS。production模式生效。

口述答案：Tree-Shaking打包移除未使用代码，减少包体积。要求使用ES Module，生产模式生效。

# 七、前端性能优化

## 30. 前端性能优化

资源层面

1. 静态资源压缩（js/css压缩，图片压缩、webp）
2. CDN加速静态资源
3. 图片懒加载、路由懒加载
4. 分包打包，减小首屏bundle体积，TreeShaking

网络层面

1. 开启HTTP缓存，减少重复请求
2. 减少http请求数量，雪碧图、资源合并；使用HTTP2多路复用

渲染层面

1. 减少重排重绘；动画优先transform
2. 长列表使用虚拟列表，只渲染视口内DOM
3. 减少大组件渲染，组件懒加载

JS层面

1. 减少长任务，耗时计算放到webWorker，不阻塞主线程

口述答案：资源压缩CDN，图片路由懒加载，分包和TreeShaking。利用HTTP缓存。减少重排重绘，长列表用虚拟列表。复杂计算放到webWorker避免阻塞主线程。
