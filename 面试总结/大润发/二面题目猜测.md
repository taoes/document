大型超市/零售系统（线上线下一体化、O2O、门店POS、WMS、供应链）面试，通常从**业务场景**切入，再深挖 **高并发、库存、订单、促销、支付、分布式一致性**。下面按模块整理常见技术面试题，并附高频题答题要点。

## 一、系统设计与业务架构

1. 设计一个大型超市线上线下一体化系统架构，包含哪些核心域？
   - 会员、商品、价格、促销、库存、购物车、订单、支付、履约、门店、POS、WMS、供应链、对账、风控。
2. 多门店、多仓、前置仓、中心仓的库存如何设计？
3. 如何保证线上订单、线下POS、门店库存一致？
4. 如何设计购物车？未登录购物车如何合并？库存不足如何提示？
5. 订单拆单规则有哪些？
   - 按门店/仓、温层（常温/冷藏/冷冻）、供应商、配送方式、履约时间拆单。
6. 如何设计自提、到家配送、即时配送履约系统？
7. 如何设计促销引擎？如何支持满减、折扣、第二件半价、买赠、优惠券叠加？
8. 如何设计价格中心？会员价、门店价、活动价、时段价、促销价如何计算？
9. 优惠券发放、领取、核销、回滚、并发防超发如何做？
10. 如何设计支付与对账系统？如何处理支付成功但订单未更新？

## 十、高频重点题答题思路

### 1. 如何防止库存超卖？
- 数据库乐观锁：`num >= 1` 条件更新，判断影响行数。
- Redis + Lua 预扣库存，异步落库。
- 分段库存：把 1000 库存分成 10 段，降低锁冲突。
- MQ 削峰，串行化扣减。
- 最终对账补偿，异常回滚。

### 2. 如何设计促销引擎？
- 规则模型：条件 + 动作，优先级、互斥、叠加。
- 计算顺序：商品级 → 订单级 → 优惠券 → 支付优惠。
- 性能：规则缓存、倒排索引、预计算、试算接口。
- 防刷：限购、风控、库存绑定。

### 3. 如何设计订单拆单？
- 按履约门店/仓、温层、供应商、配送方式拆。
- 父订单 + 子订单，支付合并，退款按比例分摊。
- 状态机 + 幂等 + MQ 异步。

### 4. 如何做支付对账？
- 渠道账单、支付流水、订单、退款流水四方核对。
- T+1 对账，差错池，自动补单/人工处理。
- 幂等、状态机、定时任务、告警。

### 5. 缓存与数据库一致性？
- 常用 Cache Aside：先更新 DB，再删除缓存。
- 延迟双删、binlog 订阅、MQ 异步补偿。
- 接受最终一致，核心交易以 DB 为准。
